## 2. Реализация

- Распараллеливание выполнено с помощью `std::thread`.
- **Стратегия:** Чередующееся распределение строк (interleaved/cyclic distribution).
- **Как работает:** поток `threadId` вычисляет строки `threadId, threadId + numThreads, threadId + 2*numThreads, ...`. Для каждой строки вызывается `mandelbrotSerial()` с параметрами `startRow = j` и `numRows = 1`.
- Замер времени каждого потока выполняется через `CycleTimer::currentSeconds()` в начале и конце `workerThreadStart()`.

### Параллельный участок кода

```cpp
void workerThreadStart(WorkerArgs * const args) {
    double startTime = CycleTimer::currentSeconds();

    // Чередующееся распределение строк (interleaved)
    for (int j = args->threadId; j < args->height; j += args->numThreads) {
        mandelbrotSerial(
            args->x0, args->y0, args->x1, args->y1,
            args->width, args->height,
            j, 1,  // startRow = j, numRows = 1
            args->maxIterations,
            args->output
        );
    }

    double endTime = CycleTimer::currentSeconds();
    printf("Thread %d: %.3f ms\n", args->threadId, (endTime - startTime) * 1000);
}
```

## 5. Анализ и ответы на пункты задания

**П.2. Линейно ли ускорение?**  
Ускорение растет почти линейно до 8 потоков (7.97x на 8 потоках). Это объясняется тем, что мы используем чередование строк, которое выравнивает нагрузку между потоками. При простом делении на блоки (верх/низ) ускорение было бы хуже из-за неравномерности вычислений (центральные пиксели фрактала требуют больше итераций).

**П.3. Время каждого потока.**  
Время выполнения потоков очень равномерное. Для 8 потоков большинство потоков работает 27.5–28.5 мс. Это объясняет высокое ускорение: все потоки завершают работу почти одновременно, и общее время определяется самым медленным потоком.

**П.4. Улучшение распределения.**  
Мы использовали чередование строк. Это позволило достичь ускорения **7.97x на 8 потоках** (View 1) и **7.64x** (View 2), что соответствует требованию задачи (7–8x).

**П.5. 16 потоков.**  
При 16 потоках ускорение составило ~8.97x, что лишь немного выше, чем на 8 потоках. Это связано с тем, что физических ядер меньше, чем потоков (Hyper-Threading). Потоки конкурируют за ресурсы процессора, и прирост производительности ограничен.
